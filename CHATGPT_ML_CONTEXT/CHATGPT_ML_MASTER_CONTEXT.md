# ChatGPT ML Master Context

This document is optimized for ChatGPT to understand the Machine Learning, Reinforcement Learning, and Profitability mechanics of the `TradingAgents` system.

## 1. Project Summary
TradingAgents is an algorithmic trading platform utilizing LLM analysts, traditional ML classifiers for signal gating, and experimental Deep RL for portfolio allocation. It features backtesting, paper trading, and live broker integration via a web dashboard.

## 2. ML Architecture & Pipeline
1. **Data Source**: Fetched via connectors in `tradingagents/dataflows/`.
2. **Feature Generation**: Computed by agents in `tradingagents/agents/analysts/` (LLM sentiment, technicals, fundamentals).
3. **Signal Generation**: Trader agents (`tradingagents/agents/trader/trader.py`) form base signals based on features.
4. **ML Gate Filtering**: The base signal is validated against `ml_models/latest/model_bundle.joblib` (Random Forest models trained by `scripts/train_ml_models.py`). Signals failing threshold probabilities (e.g., win probability < 0.6) are rejected.
5. **Risk Management**: Surviving signals hit `tradingagents/agents/risk_mgmt/` for sizing and stop limits.
6. **Backtest/Train Loop**: `backtest.py` generates massive JSON trade logs. `train_ml_models.py` trains the ML gates on these historical logs to learn which patterns lead to winning trades.
7. **RL Pipeline**: `tradingagents/rl/td3_agent.py` and `environment.py` handle an alternative continuous-action portfolio allocation model, stored in `rl_models/`.

## 3. Model Inventory Summary
- **ML Gate Models**: Random Forest Classifiers/Regressors predicting `win_probability`, `large_loss_probability`, and `expected_return`. Acts as the final execution gate.
- **RL Agent**: Twin-Delayed DDPG (TD3) predicting continuous asset allocations.

## 4. Profitability Bottlenecks
The system is at high risk of overstating backtest performance due to:
- **Overfitting**: Tree models with deep max-depth trained on small backtest samples.
- **Weak Validation**: Standard Train/Test splits instead of strict Time-Series Walk-Forward validation, risking data leakage.
- **Unrealistic Slippage**: Backtest engines and RL environments often fail to explicitly model bid/ask spreads and commissions, leading to illusory edge.
- **Uncalibrated Probabilities**: Random Forest outputs are used as hard probability thresholds without calibration (Platt Scaling).

## 5. Safe vs. Dangerous Edits
- **Safe to Edit**: `scripts/train_ml_models.py` (offline training), `tradingagents/agents/analysts/*` (feature engineering), `tradingagents/rl/environment.py` (RL simulator).
- **Dangerous (DO NOT TOUCH)**: `tradingagents/agents/risk_mgmt/*` (safety nets), `web/api/fidelity.py` (live broker execution), `tradingagents/agents/schemas.py`.
